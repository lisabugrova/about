## Баг-репорт: пример заполнения

**Учебный пример, подготовленный для портфолио. Это не дефект, найденный в Audiodoc.**

| Поле | Пример |
| --- | --- |
| ID | DEMO-UPL-01 |
| Заголовок | Добавление файлов второй порцией позволяет превысить лимит очереди в 10 файлов. |
| Область | Загрузка файлов → очередь выбранных файлов |
| Среда | Условный сценарий в настольном браузере; реальный прогон не проводился. |
| Предусловия | Пользователь авторизован; очередь пуста; баланс 3600 секунд; 11 разных корректных MP4-файлов по 10 секунд. |
| Шаг 1 | Выбрать первые 6 файлов. |
| Шаг 2 | Снова открыть диалог выбора и добавить оставшиеся 5 файлов. |
| Шаг 3 | Посчитать файлы в очереди и проверить сообщение валидации. |
| Ожидаемый результат | В очереди не больше 10 файлов. При попытке превысить лимит появляется понятное сообщение. |
| Фактический результат в учебном сценарии | В очереди все 11 файлов; сообщения об ограничении нет. |
| Влияние | Лимит очереди можно обойти, добавляя файлы несколькими порциями. |
| Предлагаемая серьёзность | Средняя: нарушено правило валидации; потеря данных не установлена. |
| Подтверждения для реального отчёта | Запись двух добавлений, итоговой очереди и состояния валидации; точные браузер/сборка и повторяемость. |

**Логика оформления:** заголовок называет ошибку и условие её появления. Наблюдение отделено от последствий: из наличия 11 файлов в очереди нельзя заключить, что все они обработались или были оплачены.
