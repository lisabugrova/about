# Пример отчёта о дефекте

Вымышленный пример, а не зарегистрированный дефект Audiodoc.

| Поле | Значение |
| --- | --- |
| ID | DEMO-EDIT-01 |
| Описание | Сохранённая правка исчезает после повторного открытия расшифровки |
| Сборка / среда | DEMO-1; Chrome на компьютере; тестовый аккаунт и искусственные данные |
| Функция | Правка → сохранение → перезагрузка |
| Влияние | Пользователь может довериться подтверждению сохранения и экспортировать неверный текст |

| Связанная проверка | Сохранность правок и регрессионные проверки редактора |

## Воспроизведение

Расшифровка содержит фразу «We meet on Monday.» Владелец вошёл в аккаунт и может редактировать текст. Браузер подключён к сети, загрузка завершена, несохранённых правок нет.

1. Заменить «Monday» на «Tuesday».
2. Дождаться завершения предусмотренного сохранения; записать видимый статус и ответ.
3. Перезагрузить страницу и открыть тот же документ.
4. Проверить предложение.

| Ожидаемый результат | Фактический результат в примере |
| --- | --- |
| После перезагрузки остаётся «We meet on Tuesday.» | Возвращается «We meet on Monday.», хотя ранее появилось подтверждение сохранения. |

## Материалы и дальнейшие проверки

К реальному отчёту приложить запись «правка → сохранение → перезагрузка», ID тестового документа, точную сборку и браузер, временные метки, частоту воспроизведения и нужные ответы сервера. Удалить личные данные.

- Сравнить подтверждение сохранения с записанным значением; проверить отложенную загрузку.
- Выяснить, зависит ли проблема от редактора, поколения документов или типа правки. Не указывать причину, пока она не проверена.
- После исправления повторить шаги и проверить пунктуацию, изменения спикеров и навигацию.
- Записать сборку и результат повторной проверки. Закрыть дефект после подтверждения исправления.
