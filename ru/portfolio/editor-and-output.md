# Редактирование расшифровки, аудио и экспорт

**Образец тестовых сценариев.** Происхождение и статус материала описаны в [сборнике проверок](test-design-workbook.md).

[Профиль](../README.md) · [Карта покрытия продукта](product-coverage.md) · [Регрессия и выпуск](regression-and-release.md)

Проверяем, что пользователь может исправить расшифровку, прослушать запись, собрать историю и экспортировать файлы без потери работы. Результат проверяем повторным открытием документов и файлов.

## Область проверки и тестовые данные

**Классический редактор** поддерживает правку сегментов и сборку историй (Story). **Бета-редактор** добавляет непрерывное редактирование и форматирование для расшифровок с метками слов. Старые документы остаются в классическом. Истории собираются из целых сегментов одной записи, без нарезки по словам.

Использовать разрешённые тестовые записи, именованные документы и истории; сохранить неизменённый исходный образец.

| Набор данных | Состав и назначение |
|---|---|
| A — интервью с метками | Два говорящих, вступление без говорящего, повторы слов, пунктуация и слышимая пауза между словами. Отметить контрольные позиции в аудио. |
| B — старая расшифровка | Текст и метки сегментов без данных по словам. |
| C — образец для правки | Короткие абзацы с метками для форматирования части слова и объединения/разделения трёх слов. |
| D — истории | Две именованные истории с разными наборами и порядком сегментов; дополнительные — для ограничения в десять версий. |
| E — длинный документ | Типичная длинная запись для продолжительной правки, переходов и прокрутки. Указать размер и длительность. |

Указывать сборку, браузер/ОС, тип документа, права и состояние сети. Редактировать с правами владельца/редактора; доступ только для чтения проверять отдельно. Для аудио и скачивания включить Safari и Chromium, для мобильных проверок — реальные устройства.

**Приоритет:** P0 — сохранность работы и корректность результата; P1 — основные функции; P2 — вспомогательные настройки и ограничения. Приоритет проверки и серьёзность дефекта — разные оценки.

## Вопросы перед проверкой

- **Субтитры:** уточнить у команды сервиса скорость чтения, длину строк, языки и правила временных меток — веб-код определяет не всё. Резервный способ проверить отдельно.
- **Связанные правки:** должны ли переименование и изменение текста затрагивать неактивные истории? Сбрасывает ли восстановление исходника какую-либо историю?
- **Сбои сохранения:** согласовать сообщения, повторные попытки и восстановление после перехода, разрыва сети и завершения приложения.
- **Подсказки о говорящих:** когда предположения ИИ должны оставаться, меняться или исчезать? Способы редактирования сейчас ведут себя по-разному.
- **Допуски:** согласовать погрешность привязки и время отклика для устройств и размеров документов. Измеренные границы можно сохранить точно; новые неизмеренные границы требуют оценки.

В [отчёте о выпуске](regression-and-release.md) указать набор данных, материалы до/после, результат и дефекты. Непроверенные сценарии отметить **«Не выполнялся»**, неуточнённые требования — **«Заблокирован / требуется уточнение»**.
