# Audiodoc Studio — тест-дизайн оплаты и зачисления времени

**Тип:** Functional & Integration Test Design  
**Область:** оплата времени обработки видео и зачисление приобретённого времени на баланс пользователя.  
**Цель:** проверить обработку платёжных операций, согласованность платёжных статусов и баланса, защиту от ошибочного или повторного начисления времени.  
**Техники:** разбиение на классы эквивалентности, таблицы решений, тестирование переходов состояний, риск-ориентированный выбор проверок.  
**Тестовая среда:** Audiodoc Studio и подключённый Payment Provider Sandbox.  
**Статус:** Test Design Sample — сценарии спроектированы, результаты выполнения не заявлены.

## Проверяемые бизнес-правила

1. Оплаченное время зачисляется только после окончательного подтверждения успешного платежа.
2. Отклонённый или окончательно отменённый платёж не изменяет баланс.
3. Одна успешно оплаченная операция приводит только к одному начислению времени.
4. Платёж, ожидающий подтверждения, не приводит к преждевременному начислению.
5. После зачисления приобретённое время доступно пользователю для обработки видео.

Эти правила используются как основа демонстрационного тест-дизайна и подлежат проверке по требованиям продукта перед выполнением.

## TC-PAY-001 — Успешная оплата и зачисление времени

**Приоритет:** High  
**Тип:** Positive / End-to-End

**Цель:** проверить, что успешная оплата приводит к корректному однократному начислению приобретённого времени.

**Предусловия:**

- Пользователь авторизован.
- Начальный баланс зафиксирован.
- Приложение подключено к платёжному sandbox.
- Доступен сценарий успешной оплаты тестовой картой.

**Шаги:**

1. Открыть раздел покупки.
2. Выбрать пакет времени.
3. Проверить соответствие итоговой стоимости выбранному тарифу.
4. Перейти к оплате банковской картой.
5. Выполнить успешную оплату в тестовой среде.
6. Дождаться окончательного подтверждения платежа.
7. Проверить изменение баланса.
8. Обновить страницу и повторно проверить баланс.
9. Проверить доступность обработки видео с использованием приобретённого времени.

**Ожидаемый результат:**

- Платёж имеет окончательный успешный статус.
- Баланс увеличился ровно на приобретённое количество времени.
- Начисление выполнено однократно.
- После обновления страницы значение баланса сохраняется.
- При соблюдении остальных условий пользователь может начать обработку видео.

## TC-PAY-002 — Отклонение платежа

**Приоритет:** High  
**Тип:** Negative / Integration

**Цель:** проверить, что отклонённый платёж не приводит к начислению времени.

**Предусловия:**

- Пользователь авторизован.
- Начальный баланс зафиксирован.
- В sandbox доступен сценарий отклонения платежа.

**Шаги:**

1. Выбрать пакет времени.
2. Перейти к оплате.
3. Использовать тестовый сценарий отклонения платежа.
4. Дождаться получения окончательного неуспешного статуса.
5. Проверить сообщение об оплате.
6. Проверить баланс пользователя.
7. Обновить страницу и повторно проверить баланс.

**Ожидаемый результат:**

- Платёж не имеет статуса успешного завершения.
- Пользователю отображается корректный результат неуспешной оплаты.
- Баланс остаётся неизменным.
- Не создаётся успешная операция начисления времени.
- Обновление страницы не изменяет результат.

## TC-PAY-003 — Отмена оплаты пользователем

**Приоритет:** High  
**Тип:** Negative / State Transition

**Цель:** проверить корректное завершение сценария при отмене оплаты пользователем.

**Предусловия:**

- Пользователь авторизован.
- Начальный баланс зафиксирован.
- Тестовая платёжная среда поддерживает отмену оплаты до её окончательного завершения.

**Шаги:**

1. Выбрать пакет времени.
2. Перейти на страницу оплаты.
3. Отменить оплату до её подтверждения.
4. Вернуться в Audiodoc Studio.
5. Проверить отображаемое состояние операции.
6. Проверить баланс пользователя.
7. Обновить страницу.

**Ожидаемый результат:**

- Незавершённая оплата не отображается как успешно оплаченная.
- При окончательно отменённом платеже время не начисляется.
- Баланс остаётся неизменным.
- Пользователь может начать новую покупку без ошибочного начисления по отменённой операции.

## TC-PAY-004 — Защита от двойного начисления времени

**Приоритет:** Critical  
**Тип:** Integration / Idempotency

**Цель:** проверить, что повторная доставка уведомления об одной и той же успешной транзакции не приводит к повторному зачислению времени.

**Предусловия:**

- Пользователь авторизован.
- Успешный тестовый платёж подтверждён.
- Приобретённое время уже однократно зачислено.
- В тестовой среде доступен разрешённый механизм повторной доставки платёжного уведомления с тем же идентификатором операции.

**Шаги:**

1. Зафиксировать идентификатор подтверждённого платежа и баланс после первого начисления.
2. Повторно отправить уведомление о **том же платеже** через тестовый механизм, не создавая новой оплаты.
3. Дождаться обработки повторного уведомления.
4. Проверить баланс пользователя.
5. Проверить количество операций начисления по данному идентификатору платежа.
6. Обновить страницу и повторно проверить баланс.

**Ожидаемый результат:**

- Повторное уведомление не создаёт дополнительного начисления времени.
- Баланс остаётся неизменным после повторной обработки события.
- Одному успешному платежу соответствует одна операция зачисления времени.
- Повторная доставка уведомления не нарушает согласованность платёжных данных.

## TC-PAY-005 — Задержка подтверждения платежа

**Приоритет:** High  
**Тип:** Integration / State Transition

**Цель:** проверить, что время не начисляется до окончательного успешного подтверждения платежа.

**Предусловия:**

- Пользователь авторизован.
- Начальный баланс зафиксирован.
- Sandbox позволяет воспроизвести платёж, ожидающий окончательного подтверждения, с последующим успешным завершением.

**Шаги:**

1. Выбрать пакет времени.
2. Перейти к оплате.
3. Создать платёж в состоянии ожидания подтверждения.
4. Проверить состояние покупки в Audiodoc Studio.
5. Проверить баланс до окончательного завершения платежа.
6. Смоделировать успешное завершение оплаты.
7. Дождаться обработки подтверждения приложением.
8. Проверить состояние операции и обновлённый баланс.
9. Обновить страницу и повторить проверку.

**Ожидаемый результат:**

- Пока оплата ожидает подтверждения, время не зачисляется.
- Пользователю не сообщается об окончательном успехе преждевременно.
- После подтверждения успешной оплаты приобретённое время начисляется однократно.
- Баланс и состояние операции остаются согласованными после обновления страницы.

## Матрица покрытия рисков

| Риск | Тест-кейс |
| --- | --- |
| Оплата прошла, время не начислено или начислено неверно | TC-PAY-001 |
| Время начислено без успешного платежа | TC-PAY-002 |
| Отменённая операция изменяет баланс | TC-PAY-003 |
| Двойное начисление по одному платежу | TC-PAY-004 |
| Преждевременное начисление до подтверждения | TC-PAY-005 |

## Критерии успешного прохождения набора

- Успешная оплата приводит к корректному однократному начислению времени.
- Неуспешные и окончательно отменённые платежи не изменяют баланс.
- Повторное подтверждение одной транзакции не приводит к повторному начислению.
- Время зачисляется только после окончательного успешного платёжного статуса.
- Баланс сохраняется после обновления страницы.
- Платёжный статус и начисленное время согласованы.
