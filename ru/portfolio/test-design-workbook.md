# QA-портфолио — путеводитель по материалам

## Типы материалов

Из исходного портфолио взяты примеры работ по загрузке и балансу и зафиксированные результаты. Расширенные и переработанные справочные сценарии подготовлены совместно с владельцем проекта и при помощи ИИ на основе изучения исходного кода продукта. Они не представлены как самостоятельно выполненные Елизаветой работы из прошлого опыта. Учебные примеры отчётов о дефекте и релизе вымышлены.

| Тип | Что означает | Где находится |
| --- | --- | --- |
| Запись о выполнении тестов | Результаты, сохранённые из существующего портфолио, с исходными ограничениями подтверждающих материалов | [Запись о выполнении](test-execution-report.md) |
| Справочный тест-дизайн | Подготовленные проверки, тестовые данные, ожидаемые результаты и приоритеты рисков; результаты выполнения не подразумеваются | Тест-дизайн по функциям и карта покрытия |
| Учебный пример | Явно обозначенный вымышленный сценарий, который показывает подход к составлению отчётов | Заполненные примеры отчётов о дефекте и релизе |
| Справочный материал по процессу | Подход к организации QA-работы, пригодный для повторного использования | Отбор регрессионных проверок и передача QA-процесса |

**Основа справочных материалов:** снимок исходного кода Audiodoc Studio, изученный 18 октября 2026 года. Развёрнутая сборка может отличаться. Перед выполнением проверок уточните целевую сборку и поддерживаемые среды. Материалы охватывают пользовательские области изученного приложения, но не все возможные входные данные и не внутреннее устройство отдельного сервиса расшифровки.

## Общие правила выполнения проверок

Для каждого прогона указываются сборка, среда, дата, тестовый набор и роль аккаунта. Для каждого выбранного тест-кейса фиксируется статус: **пройден**, **не пройден**, **заблокирован** или **не выполнен**. Сам по себе документ с тест-дизайном не имеет статуса выполнения.

Статус «пройден» требует проверки заявленного ожидаемого результата. Отделяйте подтверждённое промежуточное состояние от неподтверждённого сквозного результата. Для дефектов сохраняйте шаги воспроизведения и свидетельства без конфиденциальных данных; для заблокированных проверок указывайте недостающее условие и его влияние на релиз.

Используйте разрешённые тестовые аккаунты и синтетические либо согласованные медиафайлы. Для платёжных сценариев используйте тестовую среду провайдера или явно одобренный способ проверки. Не включайте в материалы портфолио учётные данные, платёжные реквизиты, частные аудиозаписи и расшифровки с личной информацией.
