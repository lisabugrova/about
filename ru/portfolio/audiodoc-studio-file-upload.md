# Audiodoc Studio — Загрузка и проверка медиафайлов

**План проверок.** Исходные кейсы: TC-UPL-001–006; остальные добавлены при расширении плана.

## Правила

| Правило | Ожидаемое поведение |
| --- | --- |
| UP-01 | Выбор через диалог и перетаскивание подчиняются одним правилам. |
| UP-02 | В очереди не более десяти файлов. |
| UP-03 | Ограничение на один файл — **1,782,579,200 байт** включительно: 1700 MiB, несмотря на обозначение «MB» в интерфейсе. |
| UP-04 | Регистр расширения не влияет на проверку. Допустимое расширение не гарантирует исправность файла. |
| UP-05 | Каждая строка позволяет определить файл и показывает длительность, результаты проверки и состояние обработки. Очередь можно очистить. |
| UP-06 | Длительность округляется вверх до целых секунд. При ошибке чтения метаданных её может определить резервный способ или сервер. |
| UP-07 | Доступного времени должно хватать на все выбранные файлы; см. проверки баланса. |

## Подготовка

Подготовьте тестовую учётную запись с одним часом на балансе и одиннадцать разных файлов по 10 секунд. Проверьте их имена и длительность. Между независимыми тестами очищайте очередь.

Для проверки размера нужны исправные медиафайлы по 1,782,579,199 / 1,782,579,200 / 1,782,579,201 байт. Независимо проверьте и запишите размер и длительность. Переименованные или обрезанные случайные данные не заменяют исправный MP4. Если нужных файлов нет, сквозная проверка заблокирована: имитация объекта File проверяет клиентский лимит размера, но не декодирование и обработку.

## Граничные проверки

Проверьте пустую очередь и один файл: пустую очередь запустить нельзя; исправный файл при достаточном балансе — можно. Лимит количества проверяется одним выбором и последовательными добавлениями.

Отдельно проверяйте метаданные, передачу, обработку и результат. Ориентируйтесь на реализованный двоичный лимит; надпись «MB» обсуждается отдельно от правильности порога.
