# Audiodoc Studio — Загрузка и проверка медиафайлов

**Тип материала:** справочный тест-дизайн. Исходные идентификаторы TC-UPL-001–006 сохранены; дополнительные проверки не являются зафиксированными результатами выполнения.

## Основания для проверок

| Правило | Ожидаемое поведение |
| --- | --- |
| UP-01 | Диалог выбора файлов и перетаскивание поддерживают одинаковые правила выбора. |
| UP-02 | Вся очередь выбранных файлов содержит не более десяти файлов. |
| UP-03 | Ограничение на один файл — **1,782,579,200 байт** включительно: 1700 MiB, несмотря на обозначение «MB» в интерфейсе. |
| UP-04 | Поддерживаемые расширения проверяются без учёта регистра; допустимое расширение само по себе не подтверждает корректность медиасодержимого. |
| UP-05 | Для файлов отображаются сведения, позволяющие их различать, длительность, результаты проверки и состояние обработки; очередь можно очистить. |
| UP-06 | Известная длительность округляется вверх до целых секунд; при ошибке чтения метаданных может использоваться резервный способ определения длительности, в том числе серверная проверка. |
| UP-07 | Возможность обработки зависит от доступного времени и суммарной потребности; см. тест-дизайн проверки баланса. |

## Подготовка

Используйте учётную запись с разрешённым доступом и тестовые медиафайлы, которые можно удалить. Для небольших проверок выбора установите один час доступного времени. Подготовьте одиннадцать разных файлов длительностью 10 секунд и проверьте их имена и длительность. Между независимыми тестами очищайте очередь.

Для проверки размера используйте **корректные медиафайлы, которые можно независимо проверить**, размером 1,782,579,199 / 1,782,579,200 / 1,782,579,201 байт. Сохраните перечень тестовых файлов с точным размером в байтах и длительностью. Нельзя переименовать или обрезать произвольный набор байтов и считать результат корректным MP4. Если корректные файлы граничных размеров недоступны, отметьте проверку всего пути обработки медиа как заблокированную: имитация объекта File проверяет только клиентскую границу, но не декодирование и не обработку от начала до конца.

| TC-UPL-010 | P1 | Вместе выбрать корректный файл, файл с неподдерживаемым расширением и слишком большой файл. | Для недопустимых файлов показаны соответствующие сообщения; принятый корректный файл остаётся доступным для работы; счётчик отражает принятые строки. |
| TC-UPL-011 | P1 | Выбрать файл с повреждённым содержимым и разрешённым расширением, а также файл нулевого размера. | Нет сбоя приложения или ложного результата «завершено». Ошибка метаданных, серверной проверки или обработки явно показана, дальнейшая работа возможна; проверить согласованное поведение при некорректной длительности. |
| TC-UPL-012 | P1 | Использовать проверенный медиафайл, для которого браузер не может прочитать метаданные, включая подходящий случай M4A/MP4. | Резервный путь или серверная проверка определяет длительность либо сообщает об ошибке; неизвестная длительность не трактуется молча как бесплатная обработка. |
| TC-UPL-013 | P1 | Выбрать файл с медленным чтением метаданных, сразу очистить очередь, затем выбрать другой. | Поздний результат не меняет новый выбор и не восстанавливает удалённую строку. |
| TC-UPL-014 | P1 | Выбрать два разных файла с одинаковым именем; также повторно выбрать тот же самый файл. | Строки и состояния остаются связаны с правильными файлами. Прежде чем считать намеренные дубликаты дефектом, уточнить правило продукта для повторного выбора. |
| TC-UPL-015 | P2 | Использовать длинные имена, кириллицу, пробелы и знаки препинания. | Имя файла остаётся понятным; выбор не ломается, элементы управления доступны. |
| TC-UPL-016 | P1 | Явно выбрать язык, параметры диаризации и дословной транскрипции, а также доступный проект; отправить небольшую группу файлов. | Выбранные параметры и место сохранения применяются к нужным файлам; проверить настройки получившихся документов. |

## Замечания к анализу

Нижняя граница количества файлов включает пустую очередь и один файл: при пустой очереди нельзя начать полезную обработку, а один подходящий файл можно обработать. Накопительные ограничения проверяются как одним выбором, так и последовательными добавлениями.

Проверка выбора файла не является результатом проверки совместимости кодеков. Отдельно наблюдайте чтение метаданных, передачу, обработку и итоговый результат. Сравните отображаемую единицу размера с реализованным порогом и согласуйте, нужно ли менять формулировку; двоичный порог — текущее основание для проверки, а не выдуманное требование в десятичных единицах.
