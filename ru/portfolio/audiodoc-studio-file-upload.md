# Audiodoc Studio — тест-дизайн загрузки файлов

**Функциональность:** Your documents → Upload files  
**Вид тестирования:** функциональное; позитивные и негативные проверки  
**Техники:** разбиение на классы эквивалентности (EP), анализ граничных значений (BVA), проверка альтернативных способов ввода  
**Цель:** проверить выбор файлов, валидацию очереди, ограничения загрузки и сброс выбранных файлов.

## Основание для тестирования

| ID | Требование / правило интерфейса |
| --- | --- |
| UP-01 | Пользователь может выбрать файлы через системный диалог или перетащить их в область загрузки. |
| UP-02 | В области загрузки указано ограничение **Maximum 10 files** — максимум 10 файлов. |
| UP-03 | В области загрузки указано **Up to 1700 MB each** — до 1700 МБ на файл. |
| UP-04 | Для выбранного файла отображаются имя, длительность и состояние проверки. |
| UP-05 | В интерфейсе предусмотрено действие **Clear and start over**. |
| UP-06 | Возможность начать загрузку зависит от доступного времени обработки; см. [тест-дизайн проверки баланса](audiodoc-studio-balance-validation.md). |

## Подготовка тестовых данных

- Использовать файлы поддерживаемых форматов, не содержащие конфиденциальных данных. До выполнения уточнить допустимые форматы.
- Подготовить наборы из **9, 10 и 11 файлов**, каждый меньше установленного лимита. Обеспечить достаточный баланс для суммарной длительности, чтобы проверка количества файлов не зависела от проверки баланса.
- Подготовить файлы объёмом **L − 1 байт, L и L + 1 байт**, где **L** — точный предел в байтах, соответствующий указанным 1700 МБ.
- Зафиксировать исходное количество документов; очищать очередь между независимыми проверками.
- Для drag-and-drop использовать поддерживаемый настольный браузер и локальный файл.

## Классы эквивалентности

| Параметр | Допустимый / рассматриваемый класс | Недопустимый / альтернативный класс |
| --- | --- | --- |
| Количество файлов | 1–10 | 11 и более |
| Размер одного файла | Не превышает установленный предел | Превышает предел |
| Способ выбора | Системный диалог выбора файлов | Перетаскивание (альтернативный предусмотренный способ) |
| Состояние очереди | Очередь пуста | В очереди есть выбранные файлы |

## Граничные значения

| Параметр | Тестовые значения | Цель проверки |
| --- | --- | --- |
| Количество файлов | 0, 1, 9, 10, 11 | Пустой ввод и граница максимума в 10 файлов |
| Размер файла | L − 1 байт, L, L + 1 байт | Проверка точной границы размера |

**Уточнить до выполнения:** ограничение в 10 файлов относится к одной операции или ко всей очереди; используются десятичные МБ или двоичные МиБ; как обрабатывается набор, содержащий допустимые и недопустимые файлы.

## Тест-кейсы

### TC-UPL-001 — Выбор допустимого видео через системный диалог

**Предусловия:** пользователь авторизован; доступного времени достаточно для видео; очередь пуста; подготовлен поддерживаемый видеофайл длительностью 26 мин 16 с.

1. Открыть раздел **Your documents**.
2. Нажать на область **Upload files**.
3. Выбрать видеофайл.
4. Проверить строку выбранного файла.

**Ожидаемый результат:** видео отображается в списке вместе с длительностью. При достаточном балансе и соблюдении остальных ограничений показываются **Ready to upload!** и кнопка **Start upload!**.

### TC-UPL-002 — Выбор файла перетаскиванием

**Предусловия:** как в TC-UPL-001; файловый менеджер и ОС поддерживают перетаскивание.

1. Перетащить поддерживаемый файл из файлового менеджера в область загрузки.
2. Отпустить файл над областью загрузки.
3. Проверить очередь и состояние валидации.

**Ожидаемый результат:** файл появляется в очереди без непредусмотренного дублирования; правила выбора и проверки совпадают с правилами для системного диалога.

### TC-UPL-003 — Выбор файлов на максимально допустимой границе

**Предусловия:** достаточный баланс; 10 допустимых файлов, каждый меньше предельного размера; пустая очередь.

1. Выбрать ровно **10** файлов.
2. Проверить число файлов в очереди и сообщения валидации.

**Ожидаемый результат:** максимальное ограничение соблюдено. Десять подходящих файлов могут быть выбраны при выполнении остальных условий; область действия лимита требуется подтвердить.

### TC-UPL-004 — Превышение максимально допустимого числа файлов

**Предусловия:** как в TC-UPL-003, но подготовлено **11** файлов.

1. Выбрать **11** файлов за одну операцию.
2. Проверить очередь и сообщения интерфейса.

**Ожидаемый результат:** количество принятых файлов не превышает разрешённое. Обработка превышения (отклонение всей группы либо принятие не более 10 файлов) соответствует согласованному требованию.

### TC-UPL-005 — Проверка граничных размеров файла

**Предусловия:** достаточный баланс, поддерживаемый формат; известен точный предел в байтах **L**.

1. Выбрать файл размером **L − 1 байт**.
2. Очистить очередь и выбрать файл размером **L**.
3. Очистить очередь и выбрать файл размером **L + 1 байт**.

**Ожидаемый результат:** первые два значения не нарушают заявленное ограничение; файл больше L не принимается как допустимый. При этом учитываются остальные требования к файлу.

### TC-UPL-006 — Очистка очереди выбранных файлов

**Предусловия:** выбран хотя бы один файл; доступно действие **Clear and start over**.

1. Нажать **Clear and start over**.
2. Проверить список выбранных файлов и доступные действия.

**Ожидаемый результат:** выбранные файлы удалены из очереди, форма возвращается в исходное состояние выбора файлов.
