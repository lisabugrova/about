# Передача QA-обязанностей — план и критерии готовности

**Цель:** передать регулярные QA-задачи так, чтобы новый тестировщик мог самостоятельно выбирать проверки, выполнять их, оформлять дефекты и сообщать об оставшихся рисках.

## Матрица передачи знаний

| Тема | Передаваемые материалы | Проверка самостоятельности |
| --- | --- | --- |
| Пользовательские процессы | Выбор файла → валидация → загрузка → обработка → получение результата | Объяснить основные и ошибочные сценарии без подсказок |
| Требования | Правила баланса, ограничения файлов, вопросы для уточнения | Определять основание для тестирования и выявлять неоднозначности |
| Тест-дизайн | [Загрузка файлов](audiodoc-studio-file-upload.md), [проверка баланса](audiodoc-studio-balance-validation.md) | Адаптировать существующие тест-кейсы к изменённому требованию |
| Выполнение тестов | Тестовое окружение, данные, доказательства, [отчёт](test-execution-report.md) | Самостоятельно провести небольшой цикл и записать результаты |
| Дефекты | [Шаблон баг-репорта](defect-report-template.md) | Составить воспроизводимый отчёт с доказательствами |
| Регресс | [Риск-ориентированный набор проверок](regression-and-release.md) | Обосновать отбор сценариев для конкретного изменения |
| Коммуникация по релизу | Объём проверок, Pass/Fail/Blocked, открытые проблемы, остаточные риски | Подготовить итоговый отчёт, пригодный для ревью |

## Этапы передачи

1. **Знакомство с продуктом:** обзор ключевых пользовательских процессов и участников.
2. **Анализ требований:** отделение документированных правил от открытых вопросов.
3. **Совместная проверка:** выполнение сценария проверки баланса под руководством наставника.
4. **Самостоятельный тест-дизайн:** подготовка сценариев для небольшого изменения и ревью покрытия.
5. **Практика оформления дефекта:** шаги воспроизведения, ожидаемый и фактический результаты.
6. **Выбор регресса:** отбор проверок по влиянию изменений и рискам.
7. **Оценка готовности:** самостоятельный прогон, отчёт о статусе и объяснение остаточных рисков.

## Чек-лист готовности

- [ ] Может подготовить тестовое окружение и безопасные тестовые данные.
- [ ] Объясняет процесс загрузки и проверки баланса.
- [ ] Выбирает и адаптирует техники EP, BVA, таблицы решений и переходы состояний.
- [ ] Воспроизводит отклонение и составляет информативный баг-репорт.
- [ ] Различает статусы **Pass, Fail, Blocked и Not Run**.
- [ ] Выбирает подходящий под изменение объём регрессионных проверок.
- [ ] Составляет итоговый отчёт и эскалирует нерешённые риски.
- [ ] Знает ответственных, пути эскалации и расположение документации.
