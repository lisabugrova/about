# Audiodoc Studio — ручное тестирование

[Резюме](../CV.md) · [English](../../portfolio/audiodoc-studio-case-study.md)

## Проект и примеры работ

Audiodoc Studio расшифровывает аудио и видео. Пользователь может редактировать текст и сверять его с записью. Обработка оплачивается из баланса времени.

Я работала над продуктом как QA-инженер по ручному тестированию. Здесь представлены отдельные примеры проверок загрузки и баланса времени: требования, тестовые данные, ожидаемое поведение, выбор регрессионных проверок и зафиксированные результаты.

## Задача

К одной загрузке применяются несколько правил. Файл допустимого формата и размера может оказаться слишком длинным для доступного баланса. Набор корректных файлов может превышать лимит очереди. Если данные одновременно нарушают несколько ограничений, трудно понять, какое правило определило результат.

В тест-дизайне эти условия разделены, а проверки связаны с соответствующими требованиями.

## Решения в тест-дизайне

**Выделить проверяемое правило.** Для проверки лимита очереди подготовлены одиннадцать коротких файлов и достаточный баланс для всех. Ошибка баланса не должна мешать проверке ограничения количества.

**Точно задать границы.** В примере проверяются размеры на один байт ниже лимита, ровно на границе и на один байт выше. Длительность файла для этой проверки не фиксируется; баланса должно хватать на каждый файл. Предположение о десятичных MB указано явно, чтобы перед выполнением подтвердить единицу измерения по требованиям.

**Описать состояния.** Таблица решений охватывает недостаточный и достаточный баланс, включая точное равенство длительности файла. Переходы состояний связывают выбор файла, готовность, обработку и доступ к результату.

**Выбирать регресс по влиянию изменений.** Изменения правил баланса, очереди и обработки связаны с затронутыми проверками. Шаблон отчёта о релизе включает пробелы в покрытии и оставшиеся риски.

## Зафиксированные результаты

В отчёте описан выбор 10-секундного видео при нулевом балансе: показано ожидаемое сообщение о нехватке времени, запуск обработки недоступен. Также описан сценарий с видео длительностью 26:16 при одном часе доступного времени: готовность к загрузке описана по скриншоту; об успешной обработке, скачивании и доступе к редактору сообщил тестировщик.

Наблюдения за интерфейсом и сведения со слов тестировщика в отчёте разделены. Там же указаны доступные подтверждающие материалы и дальнейшие проверки.
