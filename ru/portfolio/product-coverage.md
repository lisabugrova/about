# Audiodoc Studio — карта покрытия продукта и рисков

**Тип материала:** справочный тест-дизайн, а не отчёт о выполнении тестов.

Карта охватывает основные пользовательские области изученного приложения. Она определяет, что следует проверить и где находятся подробные сценарии; она не утверждает, что каждая функция проверена лично или что все перечисленные проверки завершились успешно.

## Приоритеты рисков

- **P0:** сохранение доступа к работе и сохранённому содержимому, корректность прав аккаунта и учёта времени обработки; сбои могут блокировать основной сценарий или причинить существенный ущерб.
- **P1:** корректность важных функций, восстановление после сбоев и совместимость.
- **P2:** оформление и удобство с меньшим влиянием на пользователя; приоритет повышается, если проблема препятствует реальной работе.

Приоритет зависит от изменений в релизе и затронутых пользователей. Недоступность критически важного элемента управления — не просто косметическая проблема.

| Язык, браузер и способы взаимодействия | Завершение сценария в среде пользователя | Неработающие элементы управления, непереведённые ошибки, непоследовательное поведение | [Совместимость](compatibility-and-exploration.md) |

## Правила, которые влияют на ожидаемый результат

- В очереди допускается не более десяти файлов суммарно, в том числе при последовательном добавлении.
- Указанное в интерфейсе ограничение «1700 MB» реализовано как **1 782 579 200 байт (1700 MiB)**.
- Определённая длительность медиафайла округляется вверх до целых секунд. Для неизвестной длительности предусмотрено определение на сервере; передача файла и проверка возможности расшифровки — отдельные этапы.
- Для доступа к документу по общей ссылке по-прежнему требуется вход в аккаунт. Закрытый доступ, просмотр и редактирование — разные режимы.
- Текущий сценарий загрузки использует актуальную модель с настройками языка, разделения по спикерам и дословной расшифровки; наличие видимого выбора модели не предполагается.
- Новый редактор с данными на уровне слов доступен отдельно в бета-версии. Работу со старыми документами и поддерживаемые функции нужно проверять отдельно.
- В изученном состоянии приложения самостоятельный возврат платежей отключён; не следует придумывать успешный сценарий возврата.

## Набор тестовых данных

| Набор | Состав и назначение |
| --- | --- |
| MEDIA-10 | Корректный 10-секундный MP4 для проверки баланса и небольших файлов |
| MEDIA-LONG | Корректный медиафайл длительностью 26:16 для зафиксированного сценария с достаточным балансом |
| COUNT-01…11 | Разные корректные 10-секундные файлы; баланс достаточен, чтобы не влиять на проверку ограничения количества |
| SIZE-LOW/EQUAL/HIGH | Корректные медиафайлы размером 1 782 579 199 / 1 782 579 200 / 1 782 579 201 байт |
| DURATION | Корректные файлы с длительностью около границы целой секунды и один подтверждённый сценарий определения длительности на сервере |
| TRANSCRIPT | Синтетический текст с двумя спикерами, известным аудио, пунктуацией, повторяющимися словами и заданным порядком сегментов |
| LEGACY | Разрешённый для проверки старый документ без данных на уровне слов и актуальный документ с такими данными |
| ACCOUNTS | Владелец A, другой авторизованный пользователь B и браузер без входа в аккаунт; отдельные контролируемые балансы |
| PAYMENT | Платежи в тестовой среде: ожидающий подтверждения, подтверждённый, отклонённый и повторное уведомление |

## Сквозные проверки перед релизом

1. **Основной путь:** вход → выбор медиафайла → проверка условий запуска → обработка → открытие → редактирование → сохранение и перезагрузка → экспорт.
2. **Доступ:** владелец создаёт документ → предоставляет просмотр или редактирование → второй аккаунт открывает документ → права меняются → доступ проверяется повторно.
3. **Учёт времени:** получение тестового баланса → обработка файла с известной длительностью → сверка результата, оставшегося времени и истории.
4. **Восстановление:** прерывание на заданном этапе → проверка сохранённого состояния → безопасная повторная попытка → проверка итогового содержимого и учёта времени.

Доступность отдельного сервиса и тестовой среды провайдера — необходимые условия проведения проверок, а не показатели работы кандидата.
