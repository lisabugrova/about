# Reference and learning map

These works inform how the *portfolio exercises* are structured. This page does not claim any examination or certification, nor imply the authors endorse the portfolio.

## Lee Copeland — *A Practitioner's Guide to Software Test Design* (2004)
Practical way to select tests from classes, boundaries, combinations, rules and behavioral models. The [test design workbook](portfolio/test-design-workbook.md) applies equivalence partitioning, boundary value analysis, decision tables, state transitions and pairwise coverage considerations.

## Sviatoslav Kulikov — «Тестирование программного обеспечения. Базовый курс»
Russian-language foundation for terminology, documented checks, defect lifecycle, and working with requirements. Used as an additional study reference; no book text is reproduced here.

## ISTQB CTFL v4.0.1
Use for common terminology including test analysis, test design, test execution, test completion, test reporting, and risk-based prioritization. [Official syllabus](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf).

## Limits of these examples
Specifications for the fictional app are assumptions. Missing or ambiguous rules are called out rather than silently invented as established product behavior. Test design is distinct from test execution, and illustrative defects are not proof of real findings.
